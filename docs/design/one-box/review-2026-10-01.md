## willow-mcp #706 — "one closeout" (af18c40, released 2.94.1)

**Verified by me in code:**
- **The friction scan is dead on human closeout.** `dispatch.py:1349` calls
  `run_closeout_instruments(..., transcript_path="")`.
  - With no transcript path, `session_friction_scan.py:193` returns
    `skipped: no_transcript_path`, and corpus-lens skips the same way.
  - The session is then marked closed, so SessionEnd (the only path that has
    the transcript) skips too.
  - Net effect: no friction scan or corpus-lens on any human closeout, and work
    done after the handoff is never scanned.
- **The `closed` marker gets wiped.** `session_start_hook.py:172` calls
  `session_enter` on every SessionStart (including compact and resume), which
  binds the session `idle`. If the session_id is reused, SessionEnd runs the
  full instruments again and the stack is written twice. Not verified: whether
  clients reuse the session_id after compact.
- **The `closed_at` branch never fires.** `session_closeout.py:28` checks a
  `closed_at` field, but `session_bind` (`dispatch.py:931-939`) rewrites the
  whole record and never writes it.

**Reported by the subagent, not individually verified:**
- **The SessionEnd skip depends on matching ids.** It keys on the `.mcp.json`
  app_id plus the payload `session_id`. If these don't match the ids the
  handoff used, the instruments run twice. Undocumented.
- **A double handoff has no idempotency guard.** It reruns the instruments and
  overwrites the receipts.
- **An empty session_id is mishandled.** SessionEnd always runs, and the
  handoff marks a shared `{app}-.json` record closed.
- **`session_bind(..., "closed")` clears `dispatch_id`.** A dispatched seat
  that closes through `session_handoff_write` is then no longer `working`, so
  `_sessions_bound_to` no longer protects its packet.
- **The handoff's stack snapshot ignores the project.** No `project_name` is
  passed; it falls back to the `WILLOW_HANDOFF_PROJECT` env, so `handoff_title`
  and `open_threads` come out empty.
- **The stack snapshot is the only instrument without try/except.** If it
  raises, the session is never marked closed.
- **Stale docs:**
  - `skills/handoff-write.md` (:64, §3–4)
  - `docs/SESSION_FLOW.md` (no human-path session states)
  - `docs/design/session-lifecycle.md:104-111` (`closed` now has two meanings)
  - `docs/deploy/native-startup.md:7`
  - the `server.py:5623` docstring
  - `hook-coverage-2026-09-28.md`
- **Already wrong before #706:** `skills/session-start.md:59` names the wrong
  stack collection.
- **Test gaps:**
  - the real instruments running from the handoff (the test mocks them out)
  - the stop hook's seat-miss path
  - verifier preservation
  - re-entry clearing `closed`
  - double or empty or mismatched ids
  - the v4 path leaving SessionEnd running
- **Tests:** 48 passed, 1 failed. The failure is `yaml` missing from the venv,
  unrelated to #706. The three skill copies agree.

## willows-grove #101 — hooks lifecycle honesty (f9cec5e / merge 1cc3cc8)

**Verified by me in code:**
- **The sealed record was hand-edited.** The PR rewrote the answers text in
  `governance/decisions/grove-hook-rows-sealed.json` but not `recorded_at` or
  `verifier`, and added no new Nestor pair.
  - The bundle `nestor/2026-09-14-grove-action-rows.json` still holds the old
    text.
  - This violates hooks proposal §6 ("the 1.4 mistake") and convergence §8
    ("a hand edit fails a pin").
  - The generator pin passes only because wiring was regenerated from the
    edited record.
- **`deposit()` (`grove_hook.py:871`) does none of what its row says.** The row
  promises kb_journal, proposed pairs and the stack snapshot. It writes a
  tool-call JSON, and its docstring calls the rest "a follow-up". The stack
  snapshot is willow-mcp's now anyway.
- **`_nestor_ask` collapses states.**
  - An empty prompt returns `unreachable / empty_prompt`, and PreCompact
    carries no prompt, so every compact prints "Nestor: unreachable".
  - A missing state defaults to `pending`.
  - There is no `empty` state, despite the PR body.
  - The reason is dropped in `_nestor_context_line`.
- **`orient()` prints to stderr** (`grove_hook.py:144`), which Claude Code does
  not inject into context.
  - The once-per-session Nestor sentinel is shared with reinject, so the boot
    line is likely never seen.
  - The PR's "Next bite" (SessionStart injects the three-state Nestor lines)
    will not pass as written.
  - The orient tests assert stderr, which locks this in.

**Reported by the subagent, not individually verified:**
- **Stop may block zero times.** `before_stop` can emit two concatenated JSON
  objects when lint and gate both block, which likely fails to parse.
- **Stop lint never covers Grove's code.** It lints `src` and `tests`; Grove
  has no `src/`, so `hooks/` and `grove/` are never linted.
- **The parity test checks the neutral `hooks/client-hooks.json`,** not
  `.claude/settings.json` or the Cursor config, and it skips the event check
  for composites.
- **The Cursor dialect is ignored.** The hooks emit Claude's
  `decision: block`; cursor-agent may also run the Claude config, so hooks
  could double-fire. There is no `.cursor/` in the repo.
- **Heimdallr's seat** (`seat/heimdallr/.claude/settings.json`) wires no
  reinject, gate or deposit. Undocumented.
- **The REINJECT lines are hardcoded** (`grove_hook.py:57-63`), not read
  "from hooks/seat.md".
- **The reach check differs from proposal §3.** It is a TCP probe on :8765
  plus `--engine offline`, where §3 says "MCP answers nestor_prefs".
- **The PR body overclaims.**
  - It cites commit `fe7b7c3`, which does not exist.
  - It credits Grove with the SessionEnd dedup, which was willow-mcp's work.
- **Stale docs:** proposal §3 and §8.3, and two test docstrings, still say
  "three lines".
- **OK:**
  - the CHANGELOG bullet
  - `Persona: willow`
  - the `Ratified-by` line, though its quote is generic, so whether it covers
    a sealed-record change is the operator's call

## The pattern
Ownership of the stack snapshot, the friction scan and closeout is undeclared
across the repo seam, and each PR assumed the other side handled it. Docs were
updated selectively, and the seal was edited to match the code.

## Against `docs/design/forge-convergence.md`
- **#706 inverts §3** ("the door is the hook, not the verb"). It made the verb
  own closeout and the hook defer, which is exactly why friction lost the
  transcript.
- **#101 is §6 step-2 work landed early,** before §6a. It changed the seal
  instead of generating the wiring from the seal and pinning it.
- **#706 implicitly answers §9 row 8** (where the durable binder session lives)
  by putting `closed` in the `session_bind` record.

## Decisions open for the operator (from the review)
1. **The sealed record.** Revert the hand edit and re-propose the text via
   Nestor, or ratify it after the fact, on the record?
2. **Friction ownership.** Recommendation: the handoff owns the stack snapshot
   and the closed marker; SessionEnd always runs friction and corpus-lens with
   the real transcript.
3. **Deposit.** Build kb_journal and pairs now, or trim the row to what it
   actually does?
4. **Cursor parity.** A requirement, or best effort?
