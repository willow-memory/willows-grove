### 2b. Second pass — "every CLI across the universe"

The reframe moves the repo from "Claude Code plus helpers" to **a spec, a
test suite every CLI is checked against, and thin per-CLI adapters**. The
repo already pointed there: `four-pieces-join.md:35` — *"The policy line is
the same everywhere; the output format is per front end."*

Four layers:

1. **Spec** — the policy as *actions*, not tool names:
   `read → allow`, `write → ask (deny if the CLI can't ask)`,
   `other → deny (shell, network, unknown, not-yet-invented)`,
   `unreadable event / crash → deny`.
2. **Core** — one pure function `decide(action) -> allow | ask | deny`.
   No I/O, no CLI knowledge.
3. **Adapters** — per CLI: parse its event, map its tool names to an action
   (anything unmapped → other), print its blocking dialect. No policy inside.
4. **Floor** — what holds where there is no hook, or the hook is switched off:
   read-only filesystem for the agent's process, writes to a staging area a
   person promotes, the vault unreadable by the agent's user (the wall
   `hook.py`'s docstring already names).

The other three pieces were already portable: **serve is a file** (every CLI
can read a file; MCP can be added later, the file is the contract); **one
script** is stdlib Python no CLI runs directly; **the key is a person**.

Proof per CLI: a shared folder of `{event, expected}` vectors, captured from
real CLIs, run against every adapter in CI, and a status table generated from
CI — **enforced / floor only / unknown** — in the three-state spirit of
INVARIANTS §1. At that point the desk said it would not write adapters for
Cursor, Gemini, Codex and others from memory. The operator answered: "Look it
up". §3–§7 are that lookup.

## 3. Method

Seven research agents ran in parallel, each scoped to a group of CLIs, plus
one on polyhook. After question 7 every agent got the same source rule, and
the two that had already finished were re-run under it:

1. the vendor's official docs page, read directly;
2. if that domain was blocked, docs committed in the vendor's official GitHub
   repo, or the source code itself;
3. only if both failed, search-engine extracts, marked as such.

No mirrors, caches, proxies or third-party blogs were to be used to get around
a block. (The desk itself, on question 6, probed `web.archive.org`,
`r.jina.ai` and `docs.cursor.com` once each before stopping; all three were
refused. Nothing was read through them.)

After question 8 the open-source agent shallow-cloned each official repo,
read the committed docs *and* the code path that runs the hook, cited
`file:line`, and trusted source over docs where they disagreed. Cloned
content was read, never executed. The one exception, deliberate and scoped:
the polyhook agent **ran the published PyPI 0.2.0 wheel** under `wasmtime`
against test payloads, to observe its real output.

## 5. Per-CLI detail

### 5.1 Claude Code — tier D
Sources: `code.claude.com/docs/en/{hooks,permission-modes,permissions,settings-reference,managed-settings,tools-reference}`, `anthropics/claude-code` `CHANGELOG.md`.

- **Event:** `PreToolUse`.
- **Config:** `hooks` in `~/.claude/settings.json`, `.claude/settings.json`,
  `.claude/settings.local.json`, managed `managed-settings.json`
  (`/etc/claude-code/`, `/Library/Application Support/ClaudeCode/`), plugins,
  skill/agent frontmatter.
  `{"hooks":{"PreToolUse":[{"matcher":"*","hooks":[{"type":"command","command":"/path/gate"}]}]}}`
- **Input:** stdin JSON — `tool_name`, `tool_input`, `tool_use_id`,
  `permission_mode`, `hook_event_name`, `cwd`, `session_id`.
- **Tool names:** read `Read`; search `Glob`, `Grep`, `LSP`; write/edit
  `Write`, `Edit`, `NotebookEdit`; shell `Bash`, `PowerShell`, **`Monitor`**;
  network `WebFetch`, `WebSearch`; MCP `mcp__<server>__<tool>`.
- **Output:** `hookSpecificOutput.permissionDecision` ∈ `allow | deny | ask |
  defer`, plus `permissionDecisionReason`. `allow` *skips the permission
  prompt*. Deny and ask rules are still evaluated whatever the hook returns.
- **Exit codes:** 2 blocks, even over a JSON `allow`. Exit 1 / other non-zero:
  "a non-blocking error and proceeds with the action". Invalid JSON:
  non-blocking. Missing or unstartable hook (e.g. 127): proceeds.
- **Timeout:** 600 s default for command hooks; on timeout the call goes to
  the normal permission flow. Agent SDK callback hooks are the exception —
  they block on timeout.
- **Fail mode:** open, except exit 2.
- **Lock:** `allowManagedHooksOnly` blocks user/project/local/plugin hooks;
  only a managed-level `disableAllHooks` disables managed hooks.
  `allowManagedPermissionRulesOnly` and `disableBypassPermissionsMode` exist.
  `ConfigChange` hooks cannot block `policy_settings` changes.
- **Can the model unwire it:** `.claude` is a protected path — writes are
  prompted in `default`/`acceptEdits`, denied in `dontAsk`, **allowed in
  `bypassPermissions`**. Settings hot-reload. Managed files are protected only
  by OS permissions (?).
- **Floor:** modes `default`, `acceptEdits`, `plan` (read-only), `auto`,
  `dontAsk` (denies anything that would prompt), `bypassPermissions`. Deny
  rules apply in every mode. Sandbox: Seatbelt (macOS), bubblewrap (Linux).
- **Landed:** hooks 1.0.38; `ask` 1.0.59 (R, changelog).
- **Ask needs a human at a terminal:** in `-p` runs nobody can answer it.

### 5.2 Gemini CLI — tier R
Sources: repo `docs/hooks/{index,reference}.md`, `docs/reference/{configuration,policy-engine,tools}.md`, `docs/admin/enterprise-controls.md`, `packages/core/src/{hooks,scheduler}/*`.

- **Event:** `BeforeTool`.
- **Config:** `hooks` in `.gemini/settings.json`, `~/.gemini/settings.json`,
  `/etc/gemini-cli/settings.json` (system), extensions. Same shape as Claude
  Code, `type:"command"`, `timeout` in ms. `hooksConfig.enabled` master
  switch; `hooksConfig.disabled` per-hook.
- **Input:** `tool_name`, `tool_input`, `mcp_context`, `original_request_name`
  + base fields.
- **Tool names:** read `read_file`, `read_many_files`, `list_directory`,
  `read_mcp_resource`; search `glob`, `grep_search`; write/edit `write_file`,
  `replace`; shell `run_shell_command`; network `web_fetch`,
  `google_web_search`; MCP `mcp_<server>_<tool>` (**single underscore**).
- **Output:** docs list only top-level `decision` (`allow` | `deny`/`block`)
  and `reason`. Source also accepts `decision:"ask"` → `PolicyDecision.ASK_USER`
  (`types.ts`, `scheduler.ts:671`). A hook `allow` does **not** override the
  policy engine.
- **Exit codes, docs:** 0 parse JSON; 2 block with stderr reason; other →
  warning, proceeds.
- **Exit codes, source (`hookRunner.ts:536-560`) — differs:** non-JSON output
  with exit 0 or **1 → allow**; non-JSON with exit ≥ 2 → deny; empty output,
  spawn error or timeout → no decision, proceeds.
- **Timeout:** 60 s default; proceeds.
- **Fail mode:** open. A crashed Python/Node hook usually exits 1 = allow.
- **Lock:** system settings override user/project, but a privileged user can
  change them. Admin Controls (strict mode, extensions) are immutable locally.
  **No managed-hooks-only setting found.** Project hooks are fingerprinted; a
  changed hook is untrusted and the user is warned. `/hooks disable-all`
  exists.
- **Can the model unwire it:** no protected-path rule for
  `.gemini/settings.json` found (?).
- **Floor:** TOML policy engine `allow` / `deny` / `ask_user` (ask_user →
  deny when non-interactive); Admin tier `/etc/gemini-cli/policies` outranks
  User, Workspace, Default (Workspace currently disabled). Modes `plan`,
  `default`, `autoEdit`, `yolo`. Sandbox `-s`: Seatbelt, Docker, Podman,
  gVisor, LXC.
- **Landed:** hooks on by default from v0.26.0 (2026-01-28), per
  `google-gemini/gemini-cli` discussion #17812. `ask` date ?.

### 5.4 OpenAI Codex CLI — tier R
Sources: `codex-rs/hooks/src/{schema.rs, engine/discovery.rs, engine/matcher.rs, engine/output_parser.rs, events/pre_tool_use.rs}`, `codex-rs/core/src/tools/hook_names.rs`, `docs/config.md`, `config/src/config_requirements.rs`, `loader/mod.rs`, `protocol/src/protocol.rs`, `sandboxing/src/seatbelt.rs`, linux-sandbox README, `codex-rs/execpolicy`.

- **Events:** `PreToolUse`, `PermissionRequest`, `PostToolUse`, plus session
  and compact events.
- **Config:** `<config dir>/hooks.json` or inline `hooks` in `config.toml`.
  Layers: system `/etc/codex`, user `~/.codex`, project `.codex/`, MDM,
  managed, session flags, requirements. Shape
  `{"hooks":{"PreToolUse":[{"matcher":"Bash|apply_patch","hooks":[{"type":"command","command":"/path/hook","timeout_sec":10}]}]}}`.
  Default timeout 600 s. Matcher: `*`, exact, `a|b`, or regex.
- **Input:** `session_id`, `turn_id`, `cwd`, `hook_event_name`, `model`,
  `permission_mode`, `tool_name`, `tool_input`, `tool_use_id`.
- **Tool names:** shell `Bash`; edits `apply_patch` with
  `tool_input = {"command": <patch>}` (matchers accept `Write`/`Edit` as
  aliases); MCP `mcp__<server>__<tool>`; `spawn_agent` (alias `Agent`).
  **No read, grep or list tool fires the hook** — only shell/unified_exec,
  apply_patch, MCP and extension handlers implement `pre_tool_use_payload`
  (code search; issue #20204). web_search: ?.
- **Output:** `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}`.
  **A deny needs a non-empty reason.** Exit 2 + stderr blocks.
  **`ask` is rejected** ("unsupported permissionDecision:ask") **and the tool
  then runs** (open request: issue #28437). `allow` is accepted only with
  `updatedInput`.
- **Fail mode:** open — crash, non-zero other than 2, timeout, malformed JSON
  all give `should_block=false` (issue #41979, v0.148, asks for opt-in
  fail-closed).
- **Lock:** `/etc/codex/requirements.toml` (Windows
  `C:\ProgramData\OpenAI\Codex\requirements.toml`), macOS MDM, cloud bundles;
  keys include `allow_managed_hooks_only` (only honoured there), `hooks`,
  `allowed_sandbox_modes`, `allowed_approval_policies`, `mcp_servers`,
  `rules`. Hooks carry a trust state (`trusted_hash`: Trusted, Managed,
  Modified, Untrusted) — an edited hook loses trust.
- **Floor:** sandbox `read-only`, `workspace-write`, `danger-full-access`,
  `external-sandbox`; approval `untrusted`, `on-request`, `granular`,
  `never`; Linux bubblewrap + seccomp network filter (Landlock legacy and
  rejected), macOS Seatbelt; execpolicy `.rules`

## 9. What this changes in the design

1. **Wrap fixes crashes; nothing fixes timeouts.** Every error path in the
   script can exit 2 / deny, and `hook.py` already does that. But a timeout or
   a hook that never starts (wrong path, no `python3`) lets the call through
   almost everywhere — Copilot included. The hook cannot be the guarantee.
   **The guarantee is each CLI's own permission config plus a sandbox; the hook
   is the finer layer on top.** Keep the hook trivially fast and set its
   timeout explicitly.
2. **"Ask" lives in the permission config, not the hook.** Hook-level ask works
   on Claude Code (D), Copilot CLI, Factory, Qwen's TUI, Gemini (source only),
   Junie (S). On Codex and through polyhook an ask becomes *running the
   tool*. Spec rule: an adapter emits `ask` only where verified; elsewhere it
   emits no decision and the CLI's native `ask` setting handles writes.
3. **"Allow reads" is not one thing.** Codex's hook never sees reads (the
   sandbox governs them). Goose has no read tool — reads go through `shell`;
   with shell denied a Goose model reads nothing. Implication for **serve**:
   deliver the served file as starting context where the CLI supports it, not
   only via a read tool.
4. **The model can unwire the hook on many CLIs.** Goose, Cline, Crush and
   Qwen keep hook config in workspace paths the model can write. Lockable:
   Claude Code, Codex, Copilot, Factory, OpenCode (and probably Cursor,
   Windsurf via system files, S). The status table needs a fourth column —
   **can the model switch it off?** — beside enforced / floor only / unknown.
5. **MCP names come in at least six shapes:** `mcp__s__t` (Claude Code, Qwen,
   Codex, Amp), `mcp_s_t` (Gemini, Crush), `s__t` (Goose), `s_t` sanitised
   (OpenCode), `mcp:s:t` (Zed), `Server(tool)` (Copilot rules), raw name
   (Continue). Only a default-deny catch-all is safe.
6. **Shell hides in other names:** Claude Code `Monitor`, Qwen `monitor` and
   `exec`, Goose `shell` (which is also its read path). Map them to *other*.
7. **No standard to target.** ACS v0.1 is fail-open by default; MCP
   annotations are untrusted by spec; polyhook is reference only.

### Revised repo contents (proposal, not built)

For each CLI:

- a **generated native permission config** (the policy line translated:
  `read allow / write ask / * deny`) — the floor;
- a **sandbox recipe** where the CLI has one (Claude Code, Codex, Gemini,
  Qwen, Factory, Copilot, Junie, Zed);
- the **hook adapter only where it adds something** (finer deny, fail-closed
  wrap, catch-all for unknown tools);
- **captured real payloads** as conformance vectors;
- a **status row**: enforced / floor only / unknown, plus *model can unwire?*,
  plus the source tier behind each cell.

**M0, the prerequisite (committed separately):** `record.py`'s `h16` cut
SHA-256 to 64 bits — one of the handoff's three `record.py` holes. It is now
`h256`, the full digest, for row hashes, `prev`, `GENESIS`, file pointers and
the run version; a hash cut back to 64 bits reads as a chain break. The other
two holes stay open.

**What `xref.py` does** (stdlib only; tested on Python 3.9.23 and 3.11.15):

1. **Arrive.** For each tracked file at a pinned commit: git's blob id (what
   GitHub holds), the same id recomputed in Python from the bytes on disk
   (`sha1("blob <len>\0" + bytes)`; symlinks hash their target, as git does),
   `blob_match`, and the system's own full SHA-256. Every folder's tree id is
   kept too. A repo is `populated`, `empty` or `unreachable` — never collapsed
   (INVARIANTS §1). `on_remote` says whether the commit is on any remote
   branch. A mismatched file is recorded and kept out of the index.
2. **Extract**, cached by SHA-256 (and an extractor version), so an unchanged
   file is never re-scanned. Q/D/OW/F ids are read from Markdown only (in
   code they collide with lint codes like `F401`); fenced code is skipped.
3. **Check.** Links (relative, and `github.com/<org>/<repo>/blob|tree|commit`
   links into any indexed repo, with `#L` ranges), `file:line` (and an
   optional `@<blob>` pin, which reports `moved` when the file changed), commit
   SHAs looked up in every repo (`ok`, `cross-repo`, `ambiguous`, or
   `external` — never "broken"), PR numbers against merge subjects, ids
   cited-never-defined and defined twice in one repo. A bare filename
   (`gate.py:840`) resolves only beside the citing file; elsewhere it is
   `unanchored`, because it could be any repo's `gate.py`.
4. **Record.** `--record BOX` writes `index.json` and `report.txt` through the
   record (pointers at full width) and appends one `xref` row with the inputs
   and both outputs' SHA-256. Unattested until the human seals.
5. **Slice**, for people: every line that defines or cites one id, tagged
   `repo@commit path:line sha256`, re-read at the indexed commit and refused if
   its bytes no longer match. Serving it to the model waits on Q19.
